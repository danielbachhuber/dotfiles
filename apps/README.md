# apps

Everything on this machine that a package manager can install, plus a record of
what it cannot.

Run `./setup.sh` on a new machine. Run `./check.sh` any time to see what is
installed, what is out of date, and what is missing; it changes nothing and
exits non-zero if anything is missing.

`check.sh` reports four states. `unmanaged` is the interesting one: the
application is in `/Applications`, but Homebrew did not put it there and will
not update it, which is true of every cask below until it is adopted.

Install Homebrew and nvm first. Neither is installed by `setup.sh`, and nvm
deliberately so: its installer appends to the shell rc, and `~/.zshrc` is a
symlink to this repository's `zshrc`, so running it from a script here would
edit a tracked file. The same has already happened once, courtesy of an
unrelated installer.

```sh
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.3/install.sh | bash
nvm install 22
```

`zshrc` already sources nvm and puts `~/.local/bin` on PATH, so a new shell
picks both up, and nvm's installer should find its lines already present.

Node matters more than it looks: the `npm` that wins on PATH belongs to another
tool and has its own global root. `setup.sh` and `check.sh` both select nvm's
default Node before touching npm, and skip the step entirely rather than
install into the wrong place. See `node.sh`. The `nvm` formula in
homebrew-core is not used: the project distributes the install script above and
discourages package-manager installs.

## What is here

| Path | Contents |
| --- | --- |
| `Brewfile` | Taps, formulae, casks, and App Store apps. |
| `npm-globals.txt` | Globally installed npm packages, one per line. |
| `setup.sh` | Trusts the taps, runs `brew bundle`, installs the npm globals, then the agent CLIs. |
| `check.sh` | Reports what is installed and at what version. Changes nothing. |
| `node.sh` | Selects nvm's Node, so both scripts use the same npm. |
| `settings/` | Application preferences worth carrying between machines. See [settings/README.md](settings/README.md). |

The Brewfile is curated rather than dumped, and only lists roots. See the
comment at the top of the file for why.

## Agent CLIs

Claude Code and Codex are installed from their vendors' scripts rather than
from Homebrew, even though casks exist for both. Each tool keeps versioned
installs under `$HOME` and updates itself, so a brew-managed copy fights its
updater and trails it: the `claude-code` cask was on 2.1.236 while the
installer gave 2.1.250.

```sh
curl -fsSL https://claude.ai/install.sh | bash
curl -fsSL https://chatgpt.com/codex/install.sh | sh
```

`setup.sh` runs both, and skips either one that is already on PATH. Both land
in `~/.local/bin`, which `zshrc` already exports. Update them with the tools'
own commands, not by re-running the installers.

## Settings

Installing an application does not configure it. `settings/` carries the
preferences worth keeping, currently Dato's, with `read.sh` to capture them
and `write.sh` to apply them. `setup.sh` does not call `write.sh`: it
overwrites live settings, so it stays something you run deliberately.

This is a short deliberate list, not general preference sync. See
[settings/README.md](settings/README.md).

## Adopting the applications on this machine

The casks were all installed by hand before this file existed, so Homebrew does
not yet know about them. `--adopt` takes ownership of the bundle already in
`/Applications` instead of downloading a second copy:

```sh
brew install --cask --adopt 1password alfred bb  # and so on
```

Nothing is removed or replaced. Afterwards `brew upgrade` maintains them.

## Installed by hand, and staying that way

Nothing below can be installed by `brew` or `mas`.

| Application | Why |
| --- | --- |
| `Writer` | writer.com's app. The `writer` cask is an unrelated markdown editor. |
| `Safari` | Ships with macOS. |
| `Claude Code URL Handler` | Generated by Claude Code. |
| `Gemini`, `Gmail` | Safari web apps, recreated from Safari's Share menu. |

Pages, Numbers, Keynote, GarageBand, and iMovie are free App Store installs and
are left out of the Brewfile on purpose: `mas` is slow and unreliable on Apple's
own titles, and they are one click each.

## After the install finishes

- Sign in to the App Store before running `setup.sh`, or every `mas` line fails.
- Unlock 1Password first; several of the steps below need credentials from it.
- Enter licence keys for Alfred and CleanShot X.
- Grant Accessibility and Screen Recording permissions to CleanShot X, Divvy,
  Alfred, and Wispr Flow. macOS will not carry these over.
- `pyenv` installs no Python of its own. Pick a version and set a global.
